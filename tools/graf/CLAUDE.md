# Graf module contract

`lib.mjs` is the dependency-free library barrel exported through `index.mjs`; `cli.mjs` only loads JSON requests and maps failures to nonzero process exit. Keep data outside this public repository. Do not add an autonomous process, provider SDK, network service, global configuration, or fallback that treats unknown work as success.

The durable boundary is `attempt_intent` before a native action and `attempt_receipt` after the caller has the actual native agent identifier. An intent is immediately `unknown` and must be reconciled explicitly. `reconcile` may terminate known-ended/not-started work only as failed/blocked/cancelled/timeout after `effect_checked:true`, reconciliation evidence, and verification of any partial effects. It never invents an ack, marks an unknown attempt passed, or auto-replays it. `retry` is a separate bounded operation and needs recorded effect-check evidence. Journal corruption, a torn tail, a checkpoint/log mismatch, and changed inputs fail closed and stay on disk for diagnosis. A writer reservation is per canonical real repository, not per run.

Every writer node predeclares repository-relative `write_paths` contained by its canonical `write_scope`. The intent stores `{path,before:{exists,sha256}}`; `record`/`reconcile` accept `{path,before,after}` only when the before state matches that intent, the after state matches the current filesystem, and the effect set exactly covers all changed allowed paths. Accepted `effect_applied` events advance only the event-sourced current state and refresh downstream packets. Never mutate the historical `baseline_input_hashes` or treat undeclared drift as an effect.

`prepare` verifies the Git base ref and prepared HEAD. Nongit fixtures require the explicit `allow_unverified_base_commit:true` escape hatch and must remain reported as unverified. The context limit applies to exact UTF-8 bytes of the complete native message, not source bytes alone; token counts derived from bytes remain estimated. Mandatory overflow fails before a run/action is created.

A paid decision appends `decision_intent` under the run lock before any provider call, then releases the lock for network I/O. The intent itself consumes `max_decision_calls`. If no matching `decision` receipt is durable after a crash, report/resume must show unknown usage as unavailable and must not replay the request.

Every added operation must reload disk, validate the manifest/event chain, preserve baseline source hashes, and update evidence through snapshots. Preserve `results/index.md` text outside the Graf managed block. Durable text/JSON files are fsynced before atomic rename. On Windows there is no portable directory-handle fsync in this implementation, so checkpoint-chain validation remains the guard for the directory entry after rename. Tests belong in `*.test.mjs` and run with `node --test tools/graf/*.test.mjs`.

Mutation locks are host-local and short-lived: hash the canonical protected directory into a separate SQLite database under `os.tmpdir()/graf-v1-locks`, then hold a `BEGIN IMMEDIATE` transaction for the complete mutation callback. Map SQLite busy to `LOCKED`; process death releases the operating-system lock, so do not add PID eviction or stale-lock deletion. Keep this database on host-local storage, never beside journal data on a synced filesystem. Durable writer reservations stay under `data_root`; terminal release atomically renames the active reservation to a unique `.released-*` history record because some synced Windows filesystems acknowledge unlink before freeing the name.
